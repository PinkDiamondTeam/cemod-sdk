# GNU Make configuration

`cemod.mk` builds, packages, verifies, and installs a `.cemod` payload. Define
project-facing variables before including it.

## Include ordering

GNU Make evaluates `wildcard`, `foreach`, and rule prerequisites while parsing
the file. Values that affect source discovery or dependencies must therefore
be final before the include:

```make
PROJECT_ROOT   := $(patsubst %/,%,$(dir $(abspath $(lastword $(MAKEFILE_LIST)))))
CEMOD_SDK_ROOT := $(PROJECT_ROOT)/third_party/cemod-sdk
CEMOD_NAME     := example-mod
CEMOD_SOURCES  := src src/platform
CEMOD_INCLUDES := include

include $(CEMOD_SDK_ROOT)/cemod.mk
```

`PROJECT_ROOT` and `CEMOD_NAME` are required. The include derives
`CEMOD_SDK_ROOT` from its own location, so the caller's value is used to find
the include but the SDK does not depend on a separately exported copy.

Third-party Make fragments commonly append to the plain `SOURCES`, `INCLUDES`,
or `DATA` variables. `cemod.mk` merges those values with `CEMOD_SOURCES`,
`CEMOD_INCLUDES`, and `CEMOD_DATA`, so such fragments may be included before
or after `cemod.mk`. Variables that change discovered file names or rule
prerequisites still belong before the include.

## Project and payload variables

| Variable | Default | Purpose |
| --- | --- | --- |
| `PROJECT_ROOT` | required | Absolute path to the consuming project |
| `CEMOD_NAME` | required | Mod ID and output basename: `out/dist/<name>.cemod` |
| `CEMOD_SOURCES` | `src` | Space-separated source directories, relative to `PROJECT_ROOT` or absolute |
| `CEMOD_INCLUDES` | `include` | Additional include directories |
| `CEMOD_DATA` | empty | Directories whose files are embedded with `bin2s` |
| `CEMOD_MANIFEST` | `$(PROJECT_ROOT)/manifest.json` | Manifest path |
| `CEMOD_TARGET` | `$(CEMOD_NAME)` | ELF target basename when it differs from the package name |
| `CEMOD_PROJECT_MAKEFILE` | `$(PROJECT_ROOT)/Makefile` | Makefile used by the recursive object-build pass |
| `CEMOD_PAYLOAD_FORMAT` | `cemod_elf` | `cemod_elf` or `wups`; independent of `execution_mode` |
| `CEMOD_ELF` | generated `$(ELF_PATH)` | Existing or generated trusted-native ELF payload |
| `CEMOD_WPS` | `$(PROJECT_ROOT)/build/plugin.wps` | WPS payload generated by the consuming project |
| `CEMOD_UI_DIR` | empty | Directory recursively packaged below `ui/`; requires package version 4 |

Supported source rules include `.c`, `.cpp`, `.s`, and `.S`. Data rules embed
`.png`, `.jpg`, `.ttf`, `.bin`, `.gsh`, `.wav`, `.mp3`, and `.ogg` inputs. File
basenames must be unique across source/data directories because the recursive
build places object files in one build directory.

## Signing variables

| Variable | Default | Purpose |
| --- | --- | --- |
| `CEMOD_PRIVATE_KEY` | empty | Ed25519 PEM private key; the packager derives and embeds the raw public key |
| `CEMOD_PUBLIC_KEY` | empty | Precomputed raw 32-byte Ed25519 public key |
| `CEMOD_SIGNATURE` | empty | Precomputed raw 64-byte detached signature |

`CEMOD_PRIVATE_KEY` cannot be combined with the detached public-key/signature
pair. `CEMOD_PUBLIC_KEY` and `CEMOD_SIGNATURE` must be supplied together.

## Compiler and linker extension hooks

| Variable | Default | Purpose |
| --- | --- | --- |
| `CEMOD_EXTRA_DEFINES` | empty | Additional `-D` flags for C and C++ |
| `CEMOD_EXTRA_CFLAGS` | empty | Additional C compiler flags |
| `CEMOD_EXTRA_CXXFLAGS` | empty | Additional C++ compiler flags |
| `CEMOD_EXTRA_LDFLAGS` | empty | Additional linker flags |
| `CEMOD_EXTRA_LIBS_GROUP` | empty | Libraries inside the SDK's `--start-group`/`--end-group` |
| `CEMOD_EXTRA_LIBS` | empty | Libraries after the SDK's library group |
| `CEMOD_EXTRA_LIBDIRS` | empty | Additional library roots; each contributes `include` and `lib` paths |
| `CEMOD_EXCLUDE_CPPFILES` | empty | `.cpp` basenames removed from automatic source discovery |
| `CEMOD_EXTRA_BUILD_DEPS` | empty | Extra prerequisites for the recursive build directory target |
| `CEMOD_EXTRA_ELF_DEPS` | empty | Extra order-only prerequisites for the final ELF link |

The default C++ mode is C++20. Trusted-native builds use PIC, the Wii U
PowerPC/EABI flags, `-fshort-wchar`, exception/unwind support, section garbage
collection, the SDK link script, and the required allocator wrappers.

## Toolchain variables

| Variable | Default | Purpose |
| --- | --- | --- |
| `DEVKITPRO` | required for local ELF builds | devkitPro root |
| `DEVKITPPC` | required for local ELF builds | devkitPPC root |
| `CEMOD_GCC` | `$(DEVKITPRO)/mcwiiu-gcc` | Codecave-safe GCC prefix |
| `CEMOD_STDLIB_ROOT` | `$(DEVKITPRO)/mcwiiu-stdlib` | 16-bit `wchar_t` newlib/libstdc++ prefix |
| `CEMOD_STDLIB_VERSION` | `14.2.0` | GCC/libstdc++ directory version |
| `CEMOD_STDLIB_ROOT_PATH` | `/vol/external01/$(CEMOD_NAME)` | Console path emitted as `MCWIIU_STDLIB_ROOT` |
| `CEMOD_STDLIB_SELF_TEST` | `0` | Value emitted as `STDLIB_SELF_TEST` |
| `USE_SYSTEM_STDLIB` | unset | Diagnostic-only use of stock devkitPPC libraries; `verify-wchar` rejects it and the result must not be distributed |
| `PYTHON` | `python3` | Python interpreter used by SDK tools |

Toolchain checks are skipped for Docker-only goals and for WUPS inspection
goals. The WUPS payload itself is compiled by the consuming project's rules.

## Targets

| Target | Behavior |
| --- | --- |
| `build`, `all` | Build the selected ELF or require the configured WPS output |
| `package` | Build, package, and run `verify-package` |
| `verify-package` | Validate the generated `.cemod` and selected payload |
| `verify-wups` | Validate `CEMOD_WPS` as a WPS/RPL image |
| `inspect-wups` | Inspect the WPS image and compare inferred requirements with the manifest |
| `verify-wchar` | Compile a check that requires 16-bit `wchar_t`; fails with `USE_SYSTEM_STDLIB=1` |
| `install` | Package and copy to `$(CEMU_DATA_DIR)/cemuextend/mods/` |
| `clean` | Remove the project's `out` directory |
| `print-project-config` | Print resolved target, payload, UI, and output paths |
| `docker-build` | Invoke the SDK Docker orchestrator for the selected payload format |
| `docker-install` | Docker-build and install the package into `CEMU_DATA_DIR` |

`install` requires `CEMU_DATA_DIR`. Docker-specific variables and Compose
configuration are documented in [Docker builds](docker-build.md).

## CMake packaging reference

The CMake helper accepts one-value arguments:

| Argument | Required | Purpose |
| --- | --- | --- |
| `TARGET` | yes | Existing CMake target whose target file is the payload |
| `MANIFEST` | yes | Manifest path |
| `PAYLOAD_FORMAT` | no | `wups` (default) or `cemod_elf` |
| `OUTPUT` | no | Output path; defaults to `<binary-dir>/<target>.cemod` |
| `UI_DIR` | no | Package-version-4 UI root |
| `PRIVATE_KEY` | no | Ed25519 PEM private key |

The helper adds an `<target>_cemod` custom target to the default build and
tracks the payload, manifest, UI files, and private key as dependencies.
